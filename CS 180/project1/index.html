Programming Project #1: Colorizing the Prokudin-Gorskii Collection

Overview

This project focuses on automatically creating color photographs from the digitized glass plate negatives of Sergei Mikhailovich Prokudin-Gorskii, who was ahead of his time in visualizing color photography. Each negative captures the same scene through three different color filters (Blue, Green, and Red, contrary to the usual RGB order), stacked vertically. The core task is to extract these three channels, align them precisely, and stack them to reconstruct a single, full-color RGB image. The main challenge lies in finding the optimal displacement vectors for the Green and Red channels relative to the Blue channel to correct for misalignments from the photographic process.

My Approach

My approach tackles the alignment problem at two different scales. First, I implemented a basic single-scale alignment algorithm that performs an exhaustive search over a small window of displacements with the starter code provided. Then, to handle the large, high-resolution TIFF images efficiently (the naive approach would have taken more than 1 minute per image), I implemented a multi-scale image pyramid algorithm. This coarse-to-fine strategy significantly speeds up the search for the optimal alignment. The primary metric used for scoring the alignment was the Normalized Cross-Correlation (NCC).

Single-Scale Alignment

The single-scale implementation works by taking the Blue channel as the fixed reference. It then iterates through a predefined search window (e.g., [-15, 15] pixels) for both the x and y axes. For each possible displacement of the Green and Red channels, it calculates the NCC against the Blue channel. The displacement vector that results in the maximum NCC is chosen as the best alignment. To avoid noisy borders from interfering with the calculation, 5% of the image was cropped before computing the NCC. This method is effective for low-resolution images where the true displacement is small.

Multi-Scale Pyramid Alignment

For large images, an exhaustive search is computationally infeasible. My solution, implemented in the align_pyramid function, resolves this by using a coarse-to-fine recursive strategy. My process_image function automatically selects this pyramid method for any image with a dimension larger than 500 pixels, ensuring efficient handling of high-resolution .tif files.

The align_pyramid function operates recursively. At each step, it downscales the channel and reference images by a factor of two using cv.resize. It then calls itself on these smaller images until it reaches a base case: either the maximum recursion depth is met, or the image becomes smaller than 50 pixels on its shortest side. At this coarsest level, it performs a single-scale search using align_channel over a [-15, 15] pixel window to get an initial estimate of the displacement.

As the recursion goes on, the displacement vector found at the coarser (smaller) level is doubled to match the scale of the current, finer level. This provides an excellent starting point for alignment. Instead of searching a large area, my code then performs a small, local refinement search in a 5x5 window (search_window = 2) around this scaled estimate. This process repeats up the pyramid, with each level refining the alignment from the previous one. This hierarchical approach dramatically reduces the search space, bringing the runtime for high-resolution images down to under a minute. Throughout all comparisons, NCC metric is used, and a 5% border continues to be effective in avoiding edge artifacts.

Challenges

I spent most of the time tuning the image-pyramid hyperparameters. I played with the number of levels, the downscale factor, and the fine-level search window. More levels (and slightly larger fine windows) helped stabilize big misalignments without blowing up runtime, but the gains tapered off quickly after 4 levels. I also varied the crop fraction during scoring so the matcher focused on the interior; small crops (~5–10%) were safest—anything larger started dropping useful signal. I tried switching to zero-mean NCC (subtracting the mean before correlation) to reduce sensitivity to brightness shifts, but in practice it didn’t improve the tricky cases much compared to plain NCC with the tuned pyramid. Overall, careful pyramid settings (≈4 levels, 0.5 downscale, ±2–3 px fine search, ~5–10% crop) worked well for me.
